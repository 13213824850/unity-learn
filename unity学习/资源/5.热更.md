# Unity代码热更方案对比

| 特性维度     | Lua (如xLua, ToLua)                | ILRuntime                               | HybridCLR (Huatuo)                              |
| -------- | --------------------------------- | --------------------------------------- | ----------------------------------------------- |
| **技术原理** | 集成Lua虚拟机，通过C#与Lua脚本交互实现热更         | 基于C#的IL解释器，在不支持JIT的平台解释执行.NET字节码        | 扩展IL2CPP运行时，增加解释器，实现"AOT + 解释"混合模式              |
| **开发体验** | 需学习Lua，维护C#与Lua的绑定代码，调试相对麻烦       | 使用C#开发，但存在限制（如反射/委托需适配，不支持ref/out）      | 近乎原生开发，无缝支持C#所有特性（反射、泛型、async/await），开发习惯无影响    |
| **热更范围** | Lua脚本可热更；C#代码需通过HotFix打补丁，管理和预测性差 | 热更工程中的代码可以热更，但无法热更普通的C#代码               | 任意C#代码均可热更，只需将对应的DLL加载到IL2CPP虚拟机                |
| **性能表现** | 脚本解释执行，复杂计算性能较差；调用C# API需类型转换     | 在iOS等无JIT平台，数值计算等纯脚本循环性能较低；调用C# API效率尚可 | 性能接近原生；热更代码直接映射Native内存；新版本发布后，热更代码转为原生执行，无解释损耗 |
| **适用场景** | UI、任务等频繁修改的业务逻辑                   | 中小型项目，希望主要使用C#进行热更                      | 中大型项目，追求高性能和原生开发体验                              |
|          |                                   | 1. 不支持jit的平台解释执行 2.要适配写热更代码             | 热更部分解释执行                                        |
|          |                                   |                                         |                                                 |

#### HybridCLR 热更重启限制（商业版）

| 需要重启的场景 | 不需要重启的场景     |
| ------- | ------------ |
| 加载新的程序集 | 更新已有方法的方法体逻辑 |
| 添加新的类型  | 修改已有方法的实现    |
| 添加新的方法  | 修复函数内部的算法或逻辑 |
